# 玩法运行唯一性：全局同时只有一个玩法在跑，游戏与插件互斥

**背景**：游戏和插件都占用设备映射、都连 bridge 驱动同一批物理设备（含电击器）。设计用单数 `active-plugin.json` 已隐含"同时一个插件"。需明确游戏/插件之间、以及重复启动的语义。

**决定**：全局同一时刻只允许一个玩法（游戏 **或** 插件）处于运行状态，两者互斥，共用这一唯一性约束。启动新玩法时，若已有玩法在跑，**自动停掉旧玩法**再启动新的（不拦、不提示）。

**设备复位（硬约束）**：任何玩法/插件**退出时**、以及**新玩法启动时**（顶掉旧玩法的那一步），必须对当次设备映射涉及的所有设备执行**设备复位**——即对每个设备按其能力逐一调 `stop`（`shock stop → shock:0`、`strength stop → power:0` 等），使设备回到停止态。设备侧无统一的 `close` 操作，"复位"即逐能力 `stop` 的组合动作。

**为什么**：物理电击设备在同一时刻被两个玩法驱动没有合理语义，只会互相打架甚至叠加危险。单个 `active-plugin.json` 天然只支持一个，将其显式化为"玩法互斥"最自然。自动顶掉最顺滑；而顶掉/退出时强制复位，避免旧玩法把电击开着就被切走或页面直接关闭导致设备卡在通电态。

**后果**：重复启动、游戏+插件并存等情况都被这一约束统一挡下。设备复位需在"玩法切换/退出"的公共路径上强制执行，不能只依赖玩法自己在正常流程里 stop（异常退出、直接关页面也要兜底复位）。若未来出现"同时多设备、多玩法并行"的真实需求，需重审——届时设备占用需从"全局唯一"改为"按物理设备粒度互斥"。关联 [[0005-backend-authoritative-play-state]] 若后续新增。
