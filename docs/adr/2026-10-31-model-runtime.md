# 客户端本地模型运行时

用户实测时，云端语音识别偶尔要 4～15 秒。对比实测（`tmp/asr-compare/report.md`）显示，本地 SenseVoice int8 每段只要 0.35 秒，错字率 1.4%。用户同意在本地运行模型，并要求：
- 模型相关的东西都放在客户端（control-panel）里，游戏端只负责调用；
- 以后其他游戏也能用别的模型；
- 有加速手段的设备优先用加速设备推理，不行再回退。

决定如下：

- **运行时放在客户端后端。** control-panel 后端新增「本地模型运行时」，统一管理模型目录、下载和校验、加速设备探测、推理子进程和任务路由。
- **游戏只按任务调用。** 游戏通过 DeviceAPI 调用"任务"（例如语音识别），不关心用的是哪个模型、哪个引擎、哪个设备。现有的 `DeviceAPI.speech` 接口不变，作为语音识别任务的入口。
- **推理设备按顺序回退：** GPU（CUDA / DirectML 等）→ CPU。用户可以在设置里指定设备。
- **本地失败时回退云端。** 以语音识别为例，顺序是：本地 → 自备 SiliconFlow key → 官方中转。
- **大文件按需下载。** 模型和 GPU 加速组件都不打进安装包，在设置页「本地模型」里按需下载，也可以删除。
- **第一个模型** 是 SenseVoiceSmall int8，跑在 sherpa-onnx 上，和云端是同一个模型，所以游戏判定逻辑不用改。
- **暂不纳入的：** 小型流式模型（Zipformer），因为错字率约 13%。「语音开始」现在用的 KWS 模型以后再迁进来。
- **手机端** 继续只用云端，接口设计保持可以移植到手机。
