# SOSEXY PID 0004 BLE 控制说明

本文是 SOSEXY PID 0004 的 BLE 控制协议和 PC 接入说明，依据 `com.funf.iot` Android APP 2.0.7 的静态代码、ADB 状态读取、BLE 广播和通知抓包整理。文中“已确认”表示代码或抓包可以交叉验证；“待验证”表示尚未为了研究主动触发对应硬件效果。

## 1. 适用范围与安全边界

- 设备：广播名 `SOSEXY`，广播 PID `0004`。
- 本文适用于 PID 0004，不应直接套用到其他型号或 PID。
- 首次测试三路强度都应从 `0` 开始，先查询状态，再单独发送一个通道的低值。
- 微电流、吸吮和机械动作必须有人看管，并准备独立的停止路径。
- 关闭 GUI、断开连接或发现异常时，应发送“全部停止”后再断开。
- 闹钟可能在延时结束后自动执行设定强度；不测试闹钟时保持禁用或发送取消闹钟。
- `0A0300`、`0A0301` 和部分闹钟字段的设备效果仍未完成硬件验证。

本文只描述协议，不要求也不建议把测试过程改成无人值守的自动控制。

## 2. 设备和 GATT

| 项目 | 值 | 说明 |
| --- | --- | --- |
| Android APP | `com.funf.iot` 2.0.7 (`versionCode=207`) | 协议来源 |
| 广播名 | `SOSEXY` | 扫描过滤条件之一 |
| 广播 PID | `0004` | Manufacturer Data 中的 PID |
| 典型会话地址 | `D3:C4:3C:57:34:F1` | 仅用于当前会话，可能变化 |
| Service | `0000ee01-0000-1000-8000-00805f9b34fb` | 自定义服务 |
| Notify | `0000ee02-0000-1000-8000-00805f9b34fb` | 设备状态通知 |
| Write | `0000ee03-0000-1000-8000-00805f9b34fb` | 下发控制报文 |
| CCCD | `00002902-0000-1000-8000-00805f9b34fb` | 开启 EE02 通知 |

BLE 地址不是稳定设备身份。扫描时优先用广播名和 PID 过滤；控制层只把地址当作本次连接定位信息。`control-panel` 的生产接入仍应遵守 `docs/adr/0008-single-control-connection-per-physical-device.md`：同一物理设备同一时间只允许一个下行控制连接。手机 APP 和 PC 工具同时连接时，连接抢占、通知缺失或写入失败都属于可能结果。

## 3. 连接流程

### 3.1 扫描

1. 确认 Windows 蓝牙服务和 BLE 适配器可用。
2. 扫描约 5-10 秒。
3. 保留 `name == SOSEXY` 的设备；如果广播名为空，可检查 Manufacturer Data 是否包含 `A1 00 04`。
4. 不要把上一次的随机地址作为永久设备 ID。地址缓存失效时，重新扫描并使用扫描返回的设备对象。

Python + Bleak 的最小扫描示例：

```python
from bleak import BleakScanner

found = await BleakScanner.discover(timeout=8, return_adv=True)
for address, (device, adv) in found.items():
    name = device.name or adv.local_name or ""
    pid_match = any(b"\xA1\x00\x04" in value
                    for value in adv.manufacturer_data.values())
    if name.upper() == "SOSEXY" or pid_match:
        print(address, name, adv.rssi)
```

### 3.2 建立 GATT 连接

1. 使用扫描返回的 `BLEDevice` 对象连接，避免只使用过期字符串地址。
2. 发现 `EE01` 服务和 `EE02`、`EE03` 两个特征。
3. 对 `EE02` 开启通知（写 CCCD `01 00` 由 Bleak 的 `start_notify` 完成）。
4. 写入 `EE03` 时使用带响应模式（`response=True`），每个物理包之间间隔约 30 ms。
5. Android APP 对每包写入等待回调，单次最多尝试 2 次；PC 实现应避免在不确定写入结果时盲目重复动作包。
6. 连接失败、GATT 服务枚举返回 `Unreachable` 时，先重新扫描再重连；实测旧地址缓存会触发这个错误。

GATT 写入响应只是 ATT 层写入成功，不是设备业务 ACK。设备状态通常通过 EE02 异步通知返回。

## 4. 逻辑报文格式

写入 EE03 前，先构造逻辑属性报文：

```text
[count:u8] + count * [property_id:u16 BE][descriptor:u8][value]
```

- 属性 ID 使用大端序。
- descriptor 低 4 位是 value 长度。
- 已观察到的 descriptor：`11` 表示 1 字节，`12` 表示 2 字节，`AF` 表示 15 字节。
- 没有发现校验和或应用层加密。
- APP 代码中的 `xorDecrypt` 实际只删除传输标记 `00`，没有执行异或。
- 属性顺序不固定，接收端应按 ID 解析而不是按位置解析。

例如震动强度 10、震动模式 2：

```text
02 0001 11 0A 0002 11 02
```

对应连续十六进制：

```text
020001110A00021102
```

当前 APP 对 PID 004 使用的模式范围是 `1..4`。不要依据其他型号的代码把 PID 004 的范围扩大到 `1..12`。

## 5. 属性表

| ID | descriptor | 方向 | 含义 | 当前已知值 |
| --- | --- | --- | --- | --- |
| `0001` | `11` | 双向 | 震动强度 | `0..100` |
| `0002` | `11` | 双向 | 震动模式 | APP 使用 `1..4` |
| `0003` | `11` | 双向 | 微电流强度 | `0..100` |
| `0004` | `11` | 双向 | 微电流模式 | APP 使用 `1..4` |
| `0005` | `11` | 上报 | 电量百分比 | `0..100` |
| `0006` | `11` | 下发 | APP 偏好枚举 | `01/02/03`，语义待验证 |
| `0007` | `11` | 双向 | 吸吮强度 | `0..100` |
| `0008` | `11` | 双向 | 吸吮模式 | APP 使用 `1..4` |
| `0009` | `11` | 双向 | 失控模式总时长 | 下发单位分钟，当前 UI 最大 179 |
| `000A` | `12` | 上报 | 失控模式剩余时长 | `u16 BE`，单位秒 |
| `000B` | `11` | 双向 | 失控功能掩码 | `0..7`，三个位的通道映射待验证 |
| `000C` | `AF` | 双向 | 闹钟 | 15 字节结构体 |
| `000D` | `11` | 双向 | 呼吸灯 | `00` 关，`01` 开 |
| `000E` | `11` | 双向 | 微电流保护 | `00` 关，`01` 开 |
| `00C8` | `11` | 下发 | 请求完整状态 | 固定 `01` |

切换新模式时，APP 在对应通道尚未播放的情况下可能自动把强度写成 `1E`（30）；滑杆第一次变化可能把模式写成 `01`。独立控制器应把强度和模式显式写入，避免依赖 APP 的隐式默认值。

## 6. 控制命令

下面的命令都是“逻辑报文”，还需要经过第 7 节的传输分包后才能写入 EE03。`VV`、`SS`、`CC` 为两位十六进制强度，`VM`、`SM`、`CM` 为两位十六进制模式。

### 6.1 三路控制

震动：

```text
02000111VV000211VM
```

吸吮：

```text
02000711SS000811SM
```

微电流：

```text
02000311CC000411CM
```

三路同时更新：

```text
06000711SS000811SM000111VV000211VM000311CC000411CM
```

只更新三路强度：

```text
03000111VV000311CC000711SS
```

### 6.2 全部停止

这是测试工具和断开流程使用的安全停止命令，把三路强度全部写为 0：

```text
03000111000003110000071100
```

示例：使用消息 ID `21` 分包后，单包写入值为：

```text
21010003000111000003110000071100
```

### 6.3 呼吸灯、微电流保护和状态查询

```text
# 呼吸灯关 / 开
01000D1100
01000D1101

# 微电流保护关 / 开
01000E1100
01000E1101

# 请求完整状态
0100C81101
```

状态查询没有动作强度，不会主动启动三路输出。建议每次连接后先发一次，再等待 EE02 通知。

### 6.4 失控模式

```text
02 0009 11 MM 000B 11 FF
```

- `MM` 是总时长，单位分钟，APP UI 当前范围 `0..179`。
- `FF` 是三路功能选择掩码，范围 `00..07`。
- APP 压缩代码可以确认三个 bit 对应 UI 的三个功能开关，但当前资料不能可靠确认 bit 与吸吮、震动、微电流的精确映射。
- 运行中设备通过 `000A 12 SSSS` 上报剩余秒数。

如果只想验证格式，先发送 `MM=00`、`FF=00`，不要直接打开未知功能位。

### 6.5 闹钟

下发属性头和 15 字节 value：

```text
01 000C AF
0009 01 LLLLLLLL SS VV CC RR TTTTTTTT
```

value 偏移如下：

| 偏移 | 长度 | 含义 |
| ---: | ---: | --- |
| 0 | 2 | APP 固定写 `0009`；设备上报曾见 `000D`，语义待验证 |
| 2 | 1 | 启用标志，`01` 启用，`00` 关闭 |
| 3 | 4 | 下发为距触发时间的分钟数，`u32 BE`；上报时 APP 当作剩余秒数 |
| 7 | 1 | 吸吮强度 `0..100` |
| 8 | 1 | 震动强度 `0..100` |
| 9 | 1 | 微电流强度 `0..100` |
| 10 | 1 | 随机档位标志，`00/01` |
| 11 | 4 | Unix 时间戳秒；APP 下发按大端，解析上报时会按小端反转 |

取消闹钟：

```text
01000CAF000900000000000000000000000000
```

设置闹钟属于可能延时执行的动作，必须在 UI 中二次确认；取消闹钟可以作为测试后的清理步骤。

### 6.6 未确认的短命令

SOSEXY 页面还会下发两条不符合属性列表格式的命令：

```text
0A0301  # 进入远程同玩状态
0A0300  # 退出远程同玩状态
```

它们的硬件效果和响应尚未主动验证。不要把它们混入属性报文，也不要在自动化流程中默认发送。

## 7. EE03 下行分包

### 7.1 分包算法

1. 在逻辑报文最前面加传输标记 `00`。
2. 将带标记的数据按每片 18 字节切分。
3. 每片前加 2 字节包头：`message_id` 和 `sequence`。
4. 同一条逻辑报文使用同一个 `message_id`，有效范围 `00..FE`。
5. `sequence` 从 `01` 开始递增。
6. 如果带标记的载荷长度刚好是 18 的倍数，额外发送只有 2 字节包头的结束包。
7. 物理 ATT value 最大 20 字节；长度为 20 表示后面还有包，小于 20 表示本条结束。

```text
ATT value = message_id sequence payload[0..18]
```

### 7.2 示例：状态查询

逻辑报文：

```text
0100C81101
```

加标记后：

```text
000100C81101
```

使用 `message_id=7A`、`sequence=01` 的 EE03 写入值：

```text
7A01000100C81101
```

### 7.3 多包发送建议

- 串行写入，不要并发调用同一个设备的 EE03。
- 相邻包等待约 30 ms。
- 业务层一次动作只建立一条逻辑报文，不能把不同动作的物理包交错发送。
- 如果写回调超时，先停止继续发送并查询连接状态；不要无条件重放可能产生动作的整条报文。
- 设备断开前，尽力发送第 6.2 节的全部停止命令。

## 8. EE02 上行拼包和状态解析

设备通知也使用 `message_id + sequence` 包头。建议 PC 实现校验包头，而不是照搬 Android APP 对包头的宽松处理。

1. 每个通知删除前 2 字节包头。
2. 校验同一条消息的 `message_id` 不变、`sequence` 从 1 连续递增。
3. 收到长度小于 20 的包时结束；只有 2 字节的包是空结束包。
4. 拼接后要求第一个字节为传输标记 `00` 并删除它。
5. 按第 4 节属性格式解析剩余逻辑报文。

本次抓到的完整状态通知：

```text
0101000C00051146000111000002110000031100
010200041100000711000008110000091100000A
0103120000000B1100000CAF000D000000000000
010400000000000000000D1101
```

去掉每包前 2 字节和拼接后的 `00` 后：

```text
0C
00051146
00011100
00021100
00031100
00041100
00071100
00081100
00091100
000A120000
000B1100
000CAF000D00000000000000000000000000
000D1101
```

解析结果：

- `0005=46`：电量 70%。
- `0001/0003/0007=00`：三路强度为 0。
- `0002/0004/0008=00`：三路当前模式为 0（设备上报值，不等同于 APP 下发模式范围）。
- `0009=00`、`000A=0000`：失控模式未运行。
- `000B=00`：失控功能位全关。
- `000C`：闹钟未启用的状态结构。
- `000D=01`：呼吸灯开启。

## 9. PC 控制器实现骨架

生产接入不应让 Electron renderer 直接持有 BLE 连接。建议把以下职责放在本机原生桥接进程或后端设备 worker 中，renderer 只调用稳定的设备层 API：

```text
扫描/连接 -> GATT 服务发现 -> EE02 通知订阅
          -> 串行写队列 -> 逻辑报文编码 -> EE03 分包写入
          -> EE02 拼包 -> 属性解析 -> 状态事件
```

最小接口可以是：

```text
scan() -> [{name, address, pid, rssi}]
connect(address) -> {service, notify, write}
disconnect() -> stopAll() + close()
queryStatus()
setChannel(channel, intensity, mode)
setLight(enabled)
setMicrocurrentProtection(enabled)
setOutOfControl(minutes, mask)
setAlarm(...)
cancelAlarm()
stopAll()
onStatus(callback)
```

控制层必须具备：

- 每台物理设备一个下行控制连接，遵守现有 ADR 约束。
- 每台设备一个串行写队列，避免包交错。
- 明确的连接、通知订阅、写入和断开状态。
- `stopAll()` 可被 UI、连接异常处理和窗口关闭调用。
- 未知属性、错误 descriptor、乱序包和缺少结束包都记录错误并停止继续发送。
- BLE 地址变化不能导致同一物理设备被当成稳定新设备；如果设备无法提供稳定身份，应只作为临时会话设备。

## 10. 手动验证流程

使用独立测试工具 `E:\smart\tools\sosexy_test_gui` 时：

1. 关闭手机 APP 的控制页，减少连接抢占。
2. 点击“扫描 SOSEXY”，选择 PID 0004 设备并连接。
3. 点击“查询状态”，确认通信日志出现 EE02 四帧状态通知。
4. 确认三路强度显示为 0，再只把一个通道设置为低强度并点击对应发送按钮。

6. 测试完成后点击红色“全部停止”。
7. 如设置过闹钟，点击“取消闹钟”；最后再断开连接。


## 11. 已知限制和待验证项

- PID 004 固件是否接受模式 `5..12`：当前 APP 只提供 `1..4`，不能据此推断固件范围。
- 属性 `0006` 的 `01/02/03` 在设备侧的具体效果。
- 属性 `000B` 三个位与吸吮、震动、微电流的准确映射。
- 闹钟 value 开头 `0009/000D` 的语义，以及上下行时间戳字节序差异是否为兼容逻辑。
- `0A0300/0A0301` 的硬件实际作用和响应。
- 不同固件是否允许手机和 PC 同时保持控制连接。

在这些项目完成受控验证前，不要把未确认命令或字段做成默认自动化行为。

## 12. control-panel 设备层映射

`control-panel` 中该型号注册为 `SOSEXY_PID0004`，品牌页会显示四个能力：

- `strength`：对外 0–255，同时映射属性 `0001`（震动）和 `0007`（吸吮）。
- `vibration`：单独写属性 `0001`，对外 0–100，直接下发，不换算。
- `suction`：单独写属性 `0007`，对外 0–100，直接下发，不换算。
- `shock`：写微电流属性 `0003`，对外 0–100，模式写入 `0004`。

设备类型定义在 `backend/devices/registry.js`，报文编码在 `backend/brands/protocols/sosexy.js`。Windows 本机桥接复用 `ycy_bridge` 的 `127.0.0.1:3001/api/send`，Electron Web Bluetooth 使用 EE01/EE02/EE03；两条路径都遵守设备层单控制连接和断开前 `stopAll` 复位。
