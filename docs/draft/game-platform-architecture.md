# 游戏投稿平台总体架构（审阅稿）

状态：draft

## 目标

- 用户无需 GitHub 即可投稿游戏。
- 首期只用一台服务器，不设审核 Worker。
- 保留现有 Control Panel 的 registry、下载校验、离线缓存和本机设备桥接。

## 总体结构

```text
投稿者 / 审核员
        |
        v
游戏网站（OSS/CDN 静态页面）
        |                 \
        | HTTPS API         \ 鉴权直传
        v                   v
游戏平台服务（Go） ------> OSS 隔离区
  - 登录、投稿与 Git 地址    - 待审核 ZIP
  - 人工审核与发布          - 已发布游戏文件/ZIP
  - registry 生成           - 网站静态文件
        |
        v
SQLite（作品、版本、审核、发布记录）
        |
        v
registry.json + 已发布游戏包
        |
        v
Control Panel（现有下载、校验、缓存、本机 bridge）
```

## 服务职责

| 部分 | 职责 |
| --- | --- |
| OSS/CDN | 承载公开网站、投稿隔离包、已发布游戏资源、ZIP 和 `registry.json`。 |
| 游戏平台服务 | 用户登录、ZIP 上传授权、Git 地址记录、投稿状态、人工审核、同步发布和 registry 生成。 |
| SQLite | 保存作品元数据、作者、版本、审核意见、发布与下架记录；单机持久卷并定期备份到 OSS。 |
| Control Panel | 继续拉取 registry，验证 ZIP 后本地运行，并经本机 bridge 控制设备。 |

## 投稿与审核流程

```text
路线 A：ZIP 投稿
  创建投稿 -> 平台签发一次性 OSS 上传授权（路径、有效期、最大大小）
  -> 浏览器直传 OSS 隔离区 -> 平台核对对象大小和归属 -> 待审核

路线 B：公开 Git 投稿
  创建投稿 -> 填写公开 Git 地址 -> 平台仅保存地址 -> 待审核
  -> 审核员在后台打开该地址查看，不在投稿时拉取或锁定 commit

审核与发布
  审核员人工本地测试 -> 退回修改 或 批准发布
  -> ZIP：从隔离区读取投稿包
  -> Git：批准时从该公开地址取得当时的内容
  -> 平台检查但不执行游戏代码，生成正式游戏资源、ZIP 和 registry
  -> 先写资源与 ZIP，最后写 registry.json
```

首期没有异步 Worker。审核员点击“批准发布”时，由平台服务同步完成文件检查、发布和 registry 更新。ZIP 上传与 Git 导入都要限制压缩包大小、解压总大小和文件数量，避免压缩包膨胀占满服务器或 OSS。

## 发布边界

- ZIP 投稿包进入 OSS 隔离区；Git 投稿只保存公开地址，不进入平台 Git 仓库，也不由 GitHub PR 审核。
- 平台服务是生产 `registry.json` 的唯一写入者，避免与现有 GitHub Actions 互相覆盖。
- 官方自研游戏仍可保留 Git 管理，但发布时应提交给同一平台服务处理。
- 已发布包按 `游戏 ID + 版本 + 内容哈希` 使用不可变路径；下架或回滚只更新 registry。
- Git 地址只作投稿与审核参考；客户端永远从 OSS 读取已发布资源和 ZIP，不会在运行时读取 Git 地址。
- Git 投稿不保存 commit，因此审核员须在“批准发布”前再次确认地址内容；最终以正式 ZIP 的内容哈希识别已发布版本。
- 首期 Git 投稿仅接受公开 HTTPS 的 GitHub/GitLab 地址；拒绝 SSH、内网和 IP 地址，批准导入时只下载受限大小的公开归档。
- 后端不执行投稿者的 HTML、JavaScript 或其他代码；人工测试在隔离的本地测试环境完成。

## 页面部署说明

不使用 SSR。公开游戏网站沿用静态站：页面在 OSS/CDN 上读取静态 `registry.json` 渲染游戏列表；游戏资源和 ZIP 也由 OSS/CDN 直接提供。每次发布只更新资源和 registry，不生成或运行页面渲染服务。

投稿、个人工作台和审核后台是低频动态操作，可由静态管理页面调用游戏平台 API；普通玩家和 Control Panel 不访问该 API。

## 单机部署

```text
同一台服务器
  - 反向代理
  - game-platform（Go，登录/投稿/审核/发布）
  - SQLite 持久卷
  - Shop（保持独立服务）

OSS/CDN
  - 游戏网站与静态资源
  - 隔离区与正式发布区
```

首期不需要 Redis、消息队列、审核 Worker 或第二台服务器。
