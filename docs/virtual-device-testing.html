虚拟设备测试系统设计

在后端模拟物理设备行为，支持脚本驱动和 API 控制，游戏开发无需真实硬件

1. 核心理念

虚拟设备 = 后端注册的模拟设备实例。它截获下行指令（记录游戏发了什么），并按脚本或 API 指令产生上行数据（模拟传感器上报、按钮事件等）。对游戏透明——游戏代码无需区分真实设备和虚拟设备。

注入点：虚拟设备在 deviceService 层面工作，跳过 MQTT/BLE Transport。下行写入被拦截记录而非发送到物理设备；上行数据通过直接调用 deviceService.handleDeviceMessage 注入，走正常的属性缓存 → 事件推送链路。

3. REST API

3.1 虚拟设备管理

// 创建虚拟设备
POST /api/virtual-devices
{ "id": "vdev_qiya_1", "type": "QIYA", "properties": { "pressure": 5.0, "temperature": 25.0 } }

// 列出所有虚拟设备
GET /api/virtual-devices
// → [{ id, type, properties, connected: true, isVirtual: true }]

// 删除虚拟设备
DELETE /api/virtual-devices/:id

// 批量创建（快速搭建测试场景）
POST /api/virtual-devices/batch
{ "devices": [
  { "id": "v_sensor", "type": "QIYA" },
  { "id": "v_motor", "type": "TD01" },
  { "id": "v_shock", "type": "DIANJI" }
] }

3.2 属性控制（模拟设备上报）

// 设置属性（等价于设备通过 MQTT 上报 method:'update'）
PUT /api/virtual-devices/:id/properties
{ "pressure": 72.5, "temperature": 26.1 }

// 读取当前属性快照
GET /api/virtual-devices/:id/properties
// → { pressure: 72.5, temperature: 26.1, report_delay_ms: 5000 }

3.3 消息事件发送（模拟设备发出消息）

// 发送消息（等价于设备 publish 到 /dpub/{id}）
POST /api/virtual-devices/:id/emit
{ "method": "low" }

// 模拟 QTZ 按钮按下
POST /api/virtual-devices/:id/emit
{ "method": "action", "action": "key_clicked" }

// 模拟 ZIDONGSUO 紧急开锁事件
POST /api/virtual-devices/:id/emit
{ "method": "action", "action": "emergency_open" }

3.4 下行指令查询

// 查看游戏对该虚拟设备发了什么指令
GET /api/virtual-devices/:id/commands
// → [
//   { ts: 1717000000, action: "invoke", capability: "strength", actionName: "set", params: { value: 128 } },
//   { ts: 1717000100, action: "writeProps", props: { power: 200 } },
// ]

// 清空指令记录
DELETE /api/virtual-devices/:id/commands

3.5 Timeline 脚本控制

// 加载并启动 timeline 脚本
POST /api/virtual-devices/:id/timeline
{ "timeline": [...], "loop": false }

// 停止正在执行的 timeline
DELETE /api/virtual-devices/:id/timeline

// 查询 timeline 执行状态
GET /api/virtual-devices/:id/timeline
// → { running: true, currentStep: 3, totalSteps: 10, elapsed: 5200 }

4. Timeline 脚本格式

Timeline 是一个步骤数组，每步定义延迟和动作。用于模拟设备随时间变化的行为序列。

{
  "timeline": [
    { "delay": 0,    "set": { "pressure": 5.0 } },
    { "delay": 2000, "set": { "pressure": 30.0 } },
    { "delay": 1000, "set": { "pressure": 60.0 } },
    { "delay": 500,  "set": { "pressure": 85.0 } },
    { "delay": 2000, "set": { "pressure": 20.0 } },
    { "delay": 3000, "emit": { "method": "action", "action": "key_clicked" } }
  ],
  "loop": true
}
字段说明
delay距上一步的延迟(ms)。支持随机范围 [1000, 3000]
set设置属性（触发属性缓存更新 + onProperty 回调）
emit发送消息（触发 onMessage 回调和能力事件匹配）
loop执行完毕后是否循环

5. 虚拟设备定义（基于固件）

每种虚拟设备的属性、范围、默认值、消息事件均从固件源码提取。

属性类型范围默认R/W说明
powerint0-2550R/WPWM强度
sleep_timeint—7200R/W休眠时间(s)

无电池、无按钮、无消息事件。

5.2 TD01 — 偏轴电机控制器

属性类型范围默认R/W说明
powerint0-2550R/WPWM强度，渐变800ms
sleep_timeint—7200R/W休眠时间(s)
batteryint0-100100R电池百分比

消息事件：{ method:"action", action:"key_boot_clicked" } — 开机键单击

5.3 QIYA — 气压传感器

属性类型范围默认R/W说明
pressurefloat~0-555.0R气压(kPa)
temperaturefloat—25.0R温度(°C)
report_delay_msint100-999995000R/W上报间隔
sleep_timeint—7200R/W休眠时间(s)
batteryint0-100100R电池百分比

自动上报：虚拟设备每 report_delay_ms 注入一次当前 pressure+temperature。无消息事件。

5.4 DIANJI — 电脉冲设备

属性类型范围默认R/W说明
voltageint0-800R/W升压目标电压(V)。safe=1时上限36V
shockint0-10R/W放电开关。1=放电中
delayint20-100030R/W放电脉冲间隔(ms)
safeint0-11R/W安全模式(限压36V)，NVS持久化
sleep_timeint—7200R/W休眠时间(s)
batteryint0-100100R电池百分比

动作消息：{ method:"dian", time:3000, voltage:30 } — 定时电击(time ms后自动停止，固件内部将shock归零)

虚拟行为：收到 dian 动作时，设置 shock=1+voltage，延迟 time ms后自动设 shock=0。

5.5 ZIDONGSUO — 自动锁

属性类型范围默认R/W说明
openint0-11R/W1=开锁(0°)，0=上锁(180°)
sleep_timeint—7200R/W休眠时间(s)
batteryint0-100100R电池百分比

消息事件：

  • { method:"action", action:"key_clicked" } — 按钮单击
  • { method:"action", action:"emergency_open" } — 紧急开锁（低电量或长按60s触发）

虚拟行为：电池低于20%连续3次检测后自动触发 emergency_open 事件并设 open=1。

5.6 QTZ — 测距及脚踏传感器

属性类型范围默认R/W说明
distancefloat0-765 mm100RVL6180X测距(mm)，3x缩放
low_bandint0-99999960R/W低阈值(mm)，NVS持久化
high_bandint0-999999150R/W高阈值(mm)，NVS持久化
report_delay_msint100-9999910000R/W上报间隔(ms)
button0int0-10R脚踏1状态
button1int0-10R脚踏2状态
sleep_timeint—7200R/W休眠时间(s)
batteryint0-100100R电池百分比

消息事件（距离阈值触发）：

  • { method:"low" } — distance 从高于 low_band 降至低于 low_band 时触发（带10mm回差）
  • { method:"high" } — distance 从低于 high_band 升至高于 high_band 时触发（带10mm回差）

虚拟行为：当通过 API 或 timeline 设置 distance 时，虚拟设备自动执行阈值判断逻辑：若 distance 从 ≥low_band 变为 <low_band，自动 emit {method:"low"}；若从 ≤high_band 变为 >high_band，自动 emit {method:"high"}。回差 10mm。

按钮：button0/button1 属性直接通过 API 设置为 0/1 即可模拟按下/释放。

属性类型范围默认R/W说明

game_* 属性（12个）：game_mode, game_duration, game_fly_dur, game_e_vol, game_e_dur, game_p1_thresh, game_p2_thresh, game_m_dur, game_m_power, game_m_step, game_cooldown, game_kegel_t。这些用于设备端内置游戏，虚拟设备不需要模拟其行为，仅保留属性读写。

6. 使用示例

场景：测试压力寸止游戏

// 1. 创建虚拟设备
POST /api/virtual-devices/batch
{
  "devices": [
    { "id": "v_sensor", "type": "QIYA", "properties": { "pressure": 5.0, "report_delay_ms": 500 } },
    { "id": "v_motor", "type": "TD01" },
    { "id": "v_shock", "type": "DIANJI" }
  ]
}

// 2. 启动游戏，deviceMap 映射到虚拟设备
// 3. 加载 timeline 模拟压力变化
POST /api/virtual-devices/v_sensor/timeline
{
  "timeline": [
    { "delay": 0,    "set": { "pressure": 5.0 } },
    { "delay": 3000, "set": { "pressure": 40.0 } },
    { "delay": 2000, "set": { "pressure": 75.0 } },
    { "delay": 1000, "set": { "pressure": 90.0 } },
    { "delay": 2000, "set": { "pressure": 15.0 } }
  ],
  "loop": true
}

// 4. 查看游戏对 motor 发了什么指令
GET /api/virtual-devices/v_motor/commands
// → [{ ts:..., capability:"strength", actionName:"set", params:{value:128} }, ...]

// 5. 查看游戏是否触发了电击
GET /api/virtual-devices/v_shock/commands
// → [{ ts:..., capability:"shock", actionName:"start", params:{voltage:20} }, ...]

场景：AI 自动化测试

// AI 通过 API 实时控制虚拟设备，观察游戏响应
// 1. AI 读取游戏 manifest 的设备需求
// 2. AI 创建对应虚拟设备
// 3. AI 按测试用例逐步设置属性/发送事件
// 4. AI 读取 commands 验证游戏行为是否符合预期
PUT /api/virtual-devices/v_sensor/properties { "pressure": 95.0 }
// 等待 1s
GET /api/virtual-devices/v_shock/commands
// 验证：游戏应在压力超阈值时触发电击

7. 实现要点

  • 虚拟设备标记：device 对象添加 isVirtual: true 字段。deviceService 在 publish 前检查此标记，虚拟设备跳过 MQTT publish，改为记录到 commandLog。
  • 上行注入：调用 deviceService.handleDeviceMessage({ topic: '/dpub/{id}', payload: JSON })，走正常的属性更新和事件推送链路。
  • 自动上报：虚拟设备创建时按 report_delay_ms 启动 setInterval，定时注入当前属性。report_delay_ms 被修改时重置 interval。
  • 阈值逻辑（QTZ）：virtualDeviceService 内部维护 low_state_flag/high_state_flag，当 distance 属性变化时执行与固件相同的阈值判断+回差逻辑，自动 emit low/high 消息。
  • 定时电击（DIANJI）：收到 method:"dian" 消息时启动 setTimeout，延迟后自动设 shock=0。
  • commandLog 上限：每设备最多保留最近 1000 条指令，FIFO 淘汰。
