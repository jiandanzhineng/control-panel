# PC / 移动端本地游戏 UI 与逻辑变化核查

核查日期：2026-10-13。场景限定为：不加入远程控制房间，在本机选择游戏、配置设备、点击开始并直接玩。

**结论：本地直接玩的体验确实有改动，不能认为这轮改造只影响远控。** PC 的部分游戏已换用宿主 Core；移动端的寸止升级版则连同绘图、语音和暂停规则一起改变。其余游戏虽然游戏文件未变，也受到公共配置页改动的影响。

本报告只调查和整理，不修改游戏。下文区分游戏内容修改、运行方式迁移产生的差异、原先就存在的跨端差异，以及尚需实机验证的风险。

## 2. 本地启动路径已经发生变化

### 2.1 PC：同一个“开始游戏”按钮，可能走两套执行方式

配置页通过 `/api/games/:id/start` 启动，后端根据 `isHostGame` 分流：

```text
本地玩法库 → 配置页 → 开始游戏
  ├─ 普通游戏 → GameCurrentView → 原 HTML / game.js → DeviceAPI
  └─ 宿主游戏 → GameRuntimeView → 原 HTML ?runtime=host
                               → UI 发送动作、渲染快照
                               → 后端 Core 执行逻辑并输出设备指令
```

当前源码中的宿主游戏为 `pressure-edging-v2`、`surge-edging`、`maid-punishment`。前两个 ID 有内置 Core，即使页面 manifest 没写 `runtime: host`，resolver 仍判为宿主游戏；女仆惩罚通过游戏包 manifest 声明宿主模式。后续安装的新游戏包也可能声明宿主模式，本报告清单不是对所有用户缓存包的穷举。

运行桥只在 URL 含 `runtime=host` 或 `runtime=remote` 时启用。直接打开无此参数的原页面仍能执行旧脚本，但**正常从客户端直接玩上述游戏，已进入宿主路径**。不能用“原 game.js 还在”证明本地玩法没变。

证据：[启动分流](../../backend/routes/games.js#L122)、[宿主判定](../../backend/game-runtime/gameCoreResolver.js#L130)、[配置页调用](../../frontend/src/views/PlayConfigView.vue#L1323)、[运行桥启用条件](../../backend/public/game-runtime-bridge.js#L22)。

### 2.2 移动端：按游戏 ID 把本地游戏送入快照宿主页

```text
本地游戏列表 → 配置页 → 开始游戏
  ├─ pressure-edging-v2 / surge-edging
  │    → /games/remote/local → LocalGameSnapshotPage
  │    → startLocal → GameHostRuntime → 内置 JS Core
  │    → RemoteGameSnapshotView 渲染游戏 HTML
  └─ 其他游戏 → GameRunPage → 原 WebView / game.js / DeviceAPI
```

这条分流不要求先连接远程房间。移动端快照页保留原 HTML 的静态内容，但删除全部 `<script>`，再注入通用快照适配器；原绘图、原语音、原交互和原国际化脚本均不运行。

移动端证据：`lib/features/games/views/game_config_page.dart:108`、`views/local_game_snapshot_page.dart:37`、`widgets/remote_game_snapshot_view.dart:159`，均位于 `lib/features/games/` 下。

### 3.1 寸止升级版：原 UI 保留较多，但暂停仍不完全等价

当前页面通过 `hostOnSnapshot` 把快照映射回原视图，原压力—强度图、阈值拖动、微调按钮、`+10 强度`、手动电击及语音调度仍有对应实现。这比移动端通用适配器保留得完整。

PC 在 `c840ece` 中恢复过原版逻辑，包括暂停不延长总时长、手动阈值上限及 `+10` 的原语义。但当前仍有一处可复现差异：

| 对照步骤 | 改造前原页面 / 当前无宿主参数的原页面 | 当前后端 Core |
|---|---|---|
| 1 秒时开始；平静期运行到 6 秒，默认每秒增加 2 | 当前强度 10、目标 10 | 当前强度 10、目标 10 |
| 6 秒时暂停 | 向设备发送 0；内部 `currentIntensity` 仍为 10 | 停止电机；内部 `currentIntensity` 改为 0 |
| 8 秒时恢复并推进一次 | 当前强度 14、目标 14 | 当前强度 4、目标 14 |

对照禁用结束前起飞期及语音，使用相同时间点和默认升速。旧页面的设备指令序列为 `0 → 10 → 0 → 14`。这说明差异不只是暂停时显示数字不同，还影响恢复后的计算起点。具体实机每帧输出仍受宿主调度影响，表中数值是指定时间序列下的结果。

证据：[原页面暂停](../../backend/games/pressure-edging-v2/game.js#L550)、[Core.pause 清零](../../backend/game-runtime/cores/pressure-edging-v2-core.js#L101)、[原图表及拖动](../../backend/games/pressure-edging-v2/game.js#L337)、[宿主语音适配](../../backend/games/pressure-edging-v2/game.js#L645)。

### 3.2 俯卧撑：明确的独立内容修改

`139d34c` 修正惩罚输出未使用配置强度的问题；`92b35e0` 把原 `vibrator` 与 `pj01` 两个电机槽合并成一个 `vibrator` 槽。这个游戏没有迁入宿主，但本轮比较区间内的本地体验确实变了：

- 现在电机槽标为“电机（TD01/PJ01）”，最多选择 1 台；不能按原方式同时映射两槽。
- 奖励和无动作惩罚共用 `vibratorIntensity`；惩罚输出使用配置值，不再直接固定为 255。
- 奖励时长 `vibratorDuration` 与惩罚时长 `pj01Duration` 仍分别存在，标签、说明及分组改变。
- 原独立“捶背”状态卡删除，统一显示“电机”。

原保存配置中只选 `pj01` 的用户应检查迁移后的 `vibrator` 映射；不能假定旧槽自动等价转换。指定移动仓库的俯卧撑游戏仍为 2.0.0，本轮没有同步上述改动。

证据：[设备槽与配置](../../backend/games/pushup-detection/index.html#L40)、[游戏输出脚本](../../backend/games/pushup-detection/game.js)、[现有输出回归测试](../../backend/tests/pushup-detection-output.test.js)。这属于比较区间内的内容修改，不能只根据时间先后归因于远控迁移。

### 3.3 女仆惩罚：页面新增操作，持续电击规则改变

新增 `shockDurationSeconds`，默认 10 秒，允许 1–10 秒；新增“⚡ 电击一次”按钮。旧自驱动逻辑在违规未解除时保持电击；宿主 Core 到达单次时长后会停止电击，即使此刻仍处于违规状态。

持续违规且没有新的触发事件时，宿主不会仅靠普通 tick 永久保持该次电击；若有新的传感器/按钮事件，是否再次触发还取决于当时状态。因此变化应准确描述为“单次电击有上限”，而不是“持续违规永远只电一次”。

Core 额外用 `lost` 状态阻止此时 TD01 开始爬升，以补偿原来依赖 `isShocking` 阻挡电机的逻辑。现有测试也明确覆盖“电击到点自动停止但违规尚未解除”的场景。这是设备输出规则的变化，不只是页面适配。

开始加锁、手动开始及结束解锁在核查代码中方向一致；没有发现“结束时锁方向被反转”的证据。

证据：[新增参数](../../backend/games/maid-punishment/index.html#L200)、[新增按钮](../../backend/games/maid-punishment/index.html#L298)、[电击时长与停止逻辑](../../backend/games/maid-punishment/game-core.js#L519)、[对应回归测试](../../backend/tests/maidPunishmentCore.test.js#L91)。

### 3.4 气压突变寸止：已经是内容改版

| 项目 | 基线 1.1.2 | 当前 1.4.1 | 对本地玩法的影响 |
|---|---|---|---|
| 检测窗口参数 | `surgeWindowMs`，默认 500 毫秒 | `surgeWindowSec`，默认 1.5 秒 | 参数键、单位、默认值改变；旧保存值需要核对 |
| 突变判定 | 当前窗口最大值 − 前一窗口平均值 | 当前气压 − 当前窗口最小值 | 同一采样序列可能更早进入边缘期 |
| 边缘释放基准 | 触发时前窗口平均值 | 触发时当前窗口最小值 | 相同回落压力可能在不同时间解除边缘期 |
| 中间压偏移 | 默认 1 kPa | 默认 0.8 kPa | 每次边缘后的中间压力不同 |
| 冷却延迟 / 最长边缘 | 默认各 5 秒 | 默认各 10 秒 | 状态持续时间改变 |
| 强度下发间隔 | 默认 2000 毫秒 | 默认 1000 毫秒 | 常规强度更新频率改变 |
| 强度上限配置范围 | 1–100 | 1–255 | 可配置的输出上限扩大，默认仍为 50 |
| 升速 | 独立 `rampRate` | 删除该参数，由 `gradualIncrease` 兼任 | 原先独立调节的两项现在耦合 |
| 中期回落 | 低于中间压力后转平静 | 新增 `midDelay`，默认 5 秒，需连续低于中间压力超过该时长 | 短暂回落不立即改变阶段，中期强度同时限制在中期上下限内 |
| 游戏内按钮 | 有 `+10 强度` | 删除该按钮 | 少了一个原本可用的手动操作 |
| 统计 | 累计刺激时间 | 剩余时间 | 展示内容改变 |
| 语音 | 原阶段提示 | 增加结束倒计时；阶段语音改为排队等待 | 播放内容和打断行为改变 |

页面和 Core 都有上述内容变化，所以即使强制使用无宿主参数的当前页面，也不能恢复基线玩法。`midDelay` 的页面说明曾写为进入中期后暂不检查回落，当前实现实际要求“连续低于中间压力”计时；验收应以明确约定的规则为准。

证据：[游戏 manifest / 页面](../../play-registry/games/surge-edging/index.html)、[页面逻辑](../../play-registry/games/surge-edging/game.js)、[实际 Core](../../backend/game-runtime/cores/surge-edging-core.js#L341)、[当前参数清单](../../backend/game-runtime/cores/surge-edging-manifest.js)。

### 3.5 PC 公共界面和生命周期：本地同样受影响

- **配置页样式变化**：公共配置页新增统一浅色卡片样式，容器从 1200 收窄至 900 像素；增加设备刷新按钮及 `maxDevices` 限制。游戏文件没变的条目也使用该页。
- **宿主运行页新增参数面板**：游戏下方可展开运行时参数表单，本地模式也展示。
- **自然结束行为变化**：宿主页收到 `ended` 后自动返回玩法库；旧自驱动游戏不会仅因游戏内部结束自动离开原页面。宿主游戏结束统计的查看窗口、结束语音完整播放因此需要回归验证。
- **离开页面行为变化**：旧 `GameCurrentView` 卸载会调用停止当前游戏；宿主运行页卸载只停止状态订阅与等待监听，后台宿主不因此停止。正常点击停止按钮仍有停止调用，但导航离页与结束游戏已不是同一件事。
- **玩法库增加标签**：宿主条目在本地列表也显示“远程无延迟”，属于可见 UI 改动。

证据：[配置页样式](../../frontend/src/views/PlayConfigView.vue#L1466)、[运行参数面板](../../frontend/src/views/GameRuntimeView.vue#L22)、[结束跳转](../../frontend/src/views/GameRuntimeView.vue#L111)、[宿主页卸载](../../frontend/src/views/GameRuntimeView.vue#L216)、[旧页卸载](../../frontend/src/views/GameCurrentView.vue#L150)、[卡片标签](../../frontend/src/views/PlayLibraryView.vue#L98)。普通 iframe 新增的 sandbox 限制只作用于 `/games/proxy/` 外部页面，内置和本地缓存游戏不加该限制。

### 4.1 原 HTML 留下来了，但原交互没有全部保留

`remoteSnapshotDocument` 删除包括 manifest、`game.js`、`i18n.js` 在内的全部 script。静态卡片和按钮仍在，但实际行为由通用适配器承担：

| 项目 | 改造前寸止升级版 | 当前本地快照页 |
|---|---|---|
| 图表含义 | 横轴气压、纵轴强度，三角阈值关系图 | 最近最多 60 份快照的序列曲线，横轴按快照顺序铺开 |
| 阈值拖动 | 可拖动中间/临界压力点 | 没有原拖动事件，也没有 `setThresholds` 动作支持 |
| 阈值微调按钮 | 原页面逻辑 | 通用适配器仍转发调整动作，但范围由移动 Core 决定 |
| 语音 | game.js 内的播放器和状态调度 | 原脚本被删除；快照适配器没有播放器实现 |
| 国际化 | 原 i18n 脚本处理页面 | i18n 脚本不执行；状态、暂停按钮文案及日期格式部分硬编码中文 |
| 数值与日志 | 游戏自己的格式化、日志顺序和数量 | 通用 `String` 渲染、最多取后 10 条日志再重建列表 |

因此当前本地宿主路径下，即使配置中 `voiceEnabled=true`，原游戏语音也不会播放。此次追加的英文化资源不能直接证明这条快照路径已完整英文化。

动态检查同时确认，当前两款宿主游戏 HTML 的普通 `data-bind` 字段均能在快照或通用特殊映射中找到对应值；没有发现所有统计字段都因名字不匹配而变成空白的问题。但字段齐全不能证明绘图、语音及交互等价。

证据：移动端 `lib/features/games/widgets/remote_game_snapshot_view.dart:159,193,224`；原压力图与拖动在 `assets/games/pressure-edging-v2/game.js`。

### 4.2 寸止升级版：当前实际 Core 与旧本地脚本存在差异

以下使用实际移动 JS Core 对照 PC 实际 Core，并结合移动基线原 game.js 核对旧行为。Core 对照直接执行 JS，不经过配置页校验；参数契约结果不代表所有输入都一定能从 PC UI 启动。

| 场景 | 移动端旧本地脚本 / 当前 PC 参照 | 当前移动 Core | 判断 |
|---|---|---|---|
| 1 秒开始、总长 1 分钟；暂停 10 秒再继续 | 结束时间仍为 61000 毫秒 | 结束时间变成 71000 毫秒 | 移动原脚本不顺延，现在顺延，明确迁移差异 |
| 暂停时已有电击 | PC 停止电机，保留本次电击计时；移动旧脚本同样不主动终止该次电击 | 同时发出 `device.shock-stop` | 暂停输出语义改变 |
| 平静期目标强度为 2 时点 `+10`，100 毫秒后推进 | 点击后目标 12，下一帧按原累积值回到 2.2 | 点击后目标 12，下一帧为 12.2 | 移动把原临时目标调整变为持续增益 |
| 暂停期间点手动电击 | 原按钮可执行，PC Core 电击次数 +1 | 不执行 | 原来可用的暂停态操作改变 |
| 临界压力为 100 时点 `+0.1` | 原手动调节可超过 100；PC 为 100.1 | 仍为 100 | 移动保留硬上限，和旧手动行为不同 |
| 中间压力 25、临界压力 20 | PC Core 接受该组参数；旧页面未加入该 Core 校验 | 抛出“中间兴奋压力必须低于临界气压” | 参数校验契约不同 |
| 中间压力输入 19.23 | PC Core 参数保留 19.23 | 归一化至 19.2 | 精度处理不同 |
| 拖动发送 `setThresholds` | PC Core 支持，示例中间压力更新至 18 | 返回“未知操作” | 不支持原拖动动作，且 UI 也未转发 |

移动基线原页面的暂停强度对照也得到 `10 → 暂停时内部仍为10 → 恢复后14`，与 PC 原页面一致。上述暂停变化并非仅由两端历史版本号不同推测。

移动端实际 Core：`assets/games/pressure-edging-v2/game-core.js`。暂停/恢复在第 85、99 行附近，动作分派在第 140 行附近，快照在第 291 行附近。当前 PC 参照为 `backend/game-runtime/cores/pressure-edging-v2-core.js`。

### 4.3 新增气压突变寸止：移动仍是旧算法，与 PC 当前版不同

移动端 1.2.1 仍使用双窗口比较、500 毫秒窗口、1 kPa 偏移、5 秒冷却和最长边缘、2000 毫秒下发间隔、独立 `rampRate`；原页面仍有 `+10 强度` 和累计刺激统计。PC 1.4.1 则采用第 3.4 节的新规则。

实际 JS 对照：开局后在 1100、1200、1300 毫秒分别输入压力 `10 → 12 → 12`，关闭结束前起飞期：

- PC 在第三个点进入 `EDGING`，电击计数为 1。
- 移动端仍为 `INITIAL_CALM`，电击计数为 0；此时旧双窗口还没有足够的前窗口样本。

这说明同名游戏同参数不保证两端得到相同结果。但移动基线没有内置这款游戏，不能把其全部差异描述成“移动已有游戏被改坏”；更准确的是“新增时引入了较旧内容，未与 PC 当前版本统一”。移动 surge Core 暂停顺延时间、暂停终止电击也与 PC 当前 Core 不同。

证据：移动 `assets/games/surge-edging/index.html`、`game-core.js:375`；PC 对应文件见第 3.4 节。

### 4.4 公共配置页变化：影响所有本地游戏

本轮把原配置页中的参数和设备控件抽到 `GameManifestParamForm`、`GameDeviceMappingForm`，开始按钮移到固定底部，增加“正在启动”的忙碌态。参数主要仍是文本框、开关、下拉框，设备仍是勾选项，并非所有控件都改成另一种视觉形式。

有一处已用组件测试复现的输入回归：

```text
想逐步输入 19.3
输入 19. → 解析为数字 → 父页 setState → didUpdateWidget 回填为 19.0
在回填后的文本末尾继续输入 3 → 得到 19.03，而不是 19.3
```

旧配置页在普通数字输入时不调用整页 `setState`，保留正在编辑的文本；新表单在每次父级重建时同步 controller，没有保留输入中的小数点及编辑态。测试模拟了当前配置页相同的受控更新方式，实际 Android/iOS 输入法及光标表现还需真机确认。一次性粘贴完整小数不等同于逐字符输入验收。

此外，manifest 模型仍未完整保留 PC 的 `min/max/step/group/device`、设备 label、`maxDevices` 等元数据。此缺口不是全部在本轮新删除的字段；它意味着“共用表单”仍不能证明 PC/移动配置规则相同。对移动端现有游戏，不能简单认定所有设备数量与参数范围都已按 PC 契约限制。

证据：移动 `lib/features/games/widgets/game_manifest_config_form.dart:51,130`、`views/game_config_page.dart:270`、`models/game_manifest.dart`。

### 4.5 本地快照路径还有两类兼容性风险

**应用生命周期。** 旧 `GameRunPage` 会启用 Wakelock，并在 `AppLifecycleListener.onPause/onDetach` 调用后台安全停止。新 `LocalGameSnapshotPage` 没有这两项逻辑；全局 `main.dart` 的生命周期回调处理诊断、mDNS 与 MQTT，没有替代本地宿主停止。因此锁屏/切后台规则已缺少原代码保障，需优先做真机验收。不能仅从 Dart 定时器代码断言操作系统后台一定继续输出。

新页的返回键通过 `PopScope` 调用 `stopLocal`，顶部也有“结束并停机”，所以“正常返回完全没有停机逻辑”并不成立；风险主要在锁屏、后台、异常销毁及生命周期替代路径。

**所选游戏包与实际执行来源。** 配置页只按 ID 判定宿主路径，`startLocal` 只收到 ID、参数和映射；Core 来源固定为 `_hostCoreAssets`，快照 HTML 来源固定为 `_assetPaths`。选中同 ID 的缓存或在线新版条目后，仍可能执行内置旧 Core、渲染内置旧 HTML，而不是所选 `GameEntry.location/version`。这有版本错配风险，即使整个过程不连接远程房间也成立。

**起始传感器读数。** 新 `DeviceGameEffectExecutor` 订阅属性变化，但映射完成时没有补读当前气压。旧 `GameRunPage` 会预置当前属性，原游戏也会调用 `readValue`。在开局时气压已经较高、尚无新属性事件的情况下，宿主可能暂按初始压力 0 执行；持续上报设备是否立即消除该差异需实机确认。

证据：移动 `lib/features/games/views/game_run_page.dart:80,101`、`views/local_game_snapshot_page.dart`、`runtime/device_game_effect_executor.dart:35`、`lib/core/remote/remote_game_host_factory.dart:14,365`、`widgets/remote_game_snapshot_view.dart:42,74`。

## 6. 建议优先级与后续本地回归清单

优先级针对“直接玩的原体验需要保持”这一目标，并不意味着已经批准修改所有玩法。

| 优先级 | 项目 | 建议 |
|---|---|---|
| P1 | 移动本地宿主语音、原压力图和拖动缺失 | 恢复每个游戏自己的渲染/交互适配，保留原语音调度；不能只复用静态 HTML |
| P1 | 移动小数输入回填 | 保留用户正在编辑的文本和光标，在明确的外部更新/提交时再归一化 |
| P1 | 移动锁屏/后台停止策略缺失 | 明确本地直接玩的后台规则，补对应生命周期路径并做真机验证 |
| P1 | 移动所选缓存包与执行 Core/HTML 错配 | 启动应使用所选包及其版本，或明确限制选择来源并显示实际运行版本 |
| P1 | 寸止升级版迁移差异 | 对照原脚本确定暂停计时、电击、恢复强度、`+10` 与阈值行为，两端逐项统一 |
| P2 | PC 女仆、俯卧撑、突变内容修改 | 将这些作为独立玩法变更确认；若要求保留旧玩法，需要明确兼容策略，不能仅回退 UI |
| P2 | PC 结束后自动跳转与导航离页 | 明确统计展示、结束语音和离页是否停止的预期，避免本地使用者误解运行状态 |
| P2 | 配置元数据与初始压力 | 补跨端参数/设备约束核对，验证开局读数及旧配置映射 |
| P3 | 移动现有下拉测试 | 缩小断言至实际菜单选项，保留去重验证，不以全局 widget 数推断产品目录 |

建议后续验收至少覆盖以下场景：

| 场景 | 重点检查 |
|---|---|
| 所有游戏从本地列表开始，不创建远程房间 | 实际运行路径、启动错误、设备映射、配置保存与恢复 |
| 寸止升级版由低压到中间压力再到临界压力 | 阶段、强度、图表含义、阈值拖动/微调、语音顺序 |
| 当前强度非零时暂停并恢复 | 暂停时输出、显示与内部强度、总时长是否顺延、恢复爬升 |
| 电击中暂停、暂停中手动电击 | 原版操作契约及自动停止时间 |
| 平静期点 `+10`，随后继续收到压力和 tick | 临时调整还是持续增益；不要只看点击瞬间数字 |
| 临界 100 再微调、小数阈值逐字符输入 | 阈值范围、精度、输入中的小数点、光标位置 |

## 7. 与已有项目约定的关系

仓库已有两条明确约定：[保留原始 UI](../adr/2026-09-29-game-original-ui.md)、[宿主迁移只改运行方式，不改游戏逻辑](../adr/2026-10-01-host-runtime-keeps-game-logic.md)。

按这一口径，移动快照页的语音、压力图、阈值拖动缺失，以及寸止升级版暂停/手动动作差异，不能认为迁移已经等价完成；PC 暂停恢复强度也仍需对齐。俯卧撑、女仆和气压突变的明确内容修改，应独立确认是否属于预期玩法升级。保留页面源码、通过现有测试或存在“恢复原版”提交，都不足以单独证明旧本地体验未改动。
