# 委托说明：SillyTavern（酒馆）设备接入

## 这是什么任务

把当前的设备控制面板（UnderSilicon, 简称 CP）接入 SillyTavern（酒馆）——让酒馆里的 NPC 角色能**自主调用**连接在 CP 上的真实电击设备。NPC 由 LLM 扮演，触发方式是 **LLM function calling**：模型在剧情里决定"电一下用户"时，自动调用一个工具函数，该函数通过 HTTP 转发到 CP，CP 再通过 MQTT 下发到物理设备。

## 你要做什么

按 [SillyTavern接入实施计划.md](./SillyTavern接入实施计划.md) 落地。两个交付物：

1. **酒馆 Server Plugin**（Node 后端代理）——挂在酒馆 Express 上，转发请求到 CP 的 REST 接口，并在中间做安全钳制（电压/时长上限、冷却、急停）。
2. **酒馆 UI 扩展**——注册 LLM 可调用的 functionTool + 设置面板 + 急停斜杠命令。

代码单独维护，不依赖 CP 代码。

## 必须参考的资料

### 第一份必读

- **`E:\develop\control-panel\docs\guides\REST_设备控制指南.md`** —— CP 的 REST 设备控制总览。所有"怎么调设备"的细节都在这里：
  - 核心接口 `POST /api/devices/:id/operations/:operationKey`，body `{params:{...}}`。
  - 电击（DIANJI 类型）用 `start`/`stop`，`start` 预设 `{voltage:24}`，可用 params 覆盖电压。
  - **REST 路径没有自动停止**（第七节注意事项第 4 条）——这是 server plugin 必须自己补 `setTimeout` 调 stop 的根本原因。
  - 端口：Electron 打包后 backend 5278、裸跑 backend 默认 3000。
  - REST 无鉴权、CORS 全放行，仅限本机调用。

## 做成什么效果（验收标准）

### 功能验收

1. **CP 运行中**，酒馆装好扩展后，在扩展设置面板选好设备 ID、设好上限，打开总开关。
2. 角色卡里 NPC 在剧情中"电击/电罚/刺激用户"时，LLM **自主调用** `trigger_shock` 工具，真实设备按指定强度和时长放电。
3. LLM 也能调用 `stop_shock` 主动停止。
4. 用户随时可用 `/shock-off` 斜杠命令急停。
5. CP 没开时，工具返回友好错误，酒馆不卡死。


## 最终要有的例子（端到端 demo）

接手人交付时，要能跑通这个端到端例子，并写进 `integrations/sillytavern/README.md`：

```
前置：CP 已启动（Electron 或裸 backend），设备已上线；酒馆已装本扩展并启用 server plugin。

1. 酒馆设置面板：
   - 设备 ID：下拉选中已上线设备
   - voltageMax：50
   - durationMax：5000ms
   - cooldownMs：3000ms
   - 总开关：开

2. 在酒馆里和 NPC 对话，剧情发展到 NPC 要电击用户。
   LLM 自动调用 trigger_shock(intensity=40, durationMs=2000)。

3. 真实设备以 voltage≈40 放电 2 秒后自动停止。

4. 在酒馆聊天框输入 /shock-off，设备立即停止（急停可用）。

5. 立刻让 LLM 再调一次 trigger_shock(intensity=99, durationMs=99999)：
   - voltage 被 clamp 到 50
   - durationMs 被 clamp 到 5000
   - 若距上次不足 3000ms，返回冷却错误
   日志文件里能看到这次"被钳制"的调用记录。
```

这个例子覆盖了：自主触发、自动停止、急停、硬上限钳制、冷却、日志。全过即验收。

## 关键决策（已定，不要改方向）

- **触发方式**：LLM function calling（不是关键词正则扫描，也不是纯手动斜杠命令）。后两者可作为附加，但主路径是 functionTool。
- **调用路径**：CP 的 **REST operations**（不是 WS bridge）。原因：REST 无会话，不和现有插件 UI / 游戏抢占单会话槽。
- **架构**：UI 扩展 + server plugin 两层（不是单层浏览器直连）。原因：CORS + 安全钳制必须在 Node 侧。
- **范围**：先出可运行骨架 + 安装说明，不追求完美。
