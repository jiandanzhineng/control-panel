manifest 规范

元数据内联在 index.html，构建脚本会校验。最小可用示例：

<script id="game-manifest" type="application/json">
{
  "id": "your-id",
  "title": "游戏显示名",
  "version": "1.0.0",
  "description": "一句话玩法说明",
  "devices": [
    { "id": "sensor", "capabilities": ["sphincterPressure"], "required": true },
    { "id": "motor",  "capabilities": ["strength"],          "required": true },
    { "id": "punish", "capabilities": ["shock"],             "required": false }
  ],
  "params": [
    { "key": "durationSec", "label": "时长(秒)", "type": "number", "default": 300 }
  ]
}
</script>
  • id 全局唯一、kebab-case，且必须等于目录名（构建强校验）；version 合法 semver（如 1.0.0）。
  • 显示名字段是 title（不是 name），缺省时回退为 id。
  • devices[].id 是逻辑设备名，玩法里用 DeviceAPI.device('<id>') 引用。
  • required:false 的设备可选，代码里 isMapped() 判断后再用。
  • 确需请求外部服务时加 "allowedOrigins": ["https://api.example.com"]——未声明的外部 origin 会被构建 lint 拦截；permissions 数组按需声明。
  • 改动已有游戏必须 bump version：CI 会对比线上 registry 内容指纹，内容变了版本没变直接构建失败。

params 参数 schema

params 是启动时用户在面板上可配的参数，运行时读 DeviceAPI.params（用户未配置时回落为 manifest 里的 default）。支持四种类型：

type面板控件可用额外字段
number数字输入min、max
string文本输入placeholder
boolean开关—
enum下拉选择"enum": ["drink", "pee"]
  • label 是显示名（可带单位，如 "电击强度(V)"），default 给安全合理的默认值。
  • required:false 的参数会收进面板「高级配置」折叠区；不设 required 则直接显示在主表单。

DeviceAPI 核心（完整版见 DeviceAPI 参考）

window.DeviceAPI 不是宿主隔空注入的——它由页面自己引入的桥接脚本创建。每个游戏页面都必须引入（构建 lint 放行 /bridge-api/ 路径；经 gameProxy 加载时它解析到面板后端）：

<script src="/bridge-api/device-api-bridge.js"></script>
// 所有设备操作前必须等通道就绪
await DeviceAPI.ready;

const dev = DeviceAPI.device('logicalId');   // 逻辑设备代理

// —— 下行（推荐走能力 invoke，有校验+映射）——
dev.invoke(capability, action, params);       // 如 ('strength','set',{value:128})
dev.writeProps(props);                         // 低层：直接写属性
dev.sendMessage(msg);                          // 低层：发原始消息

// —— 上行订阅 ——
dev.on(capability, event, cb);                 // 能力事件，cb(data)
dev.onValue(capability, cb);                   // 能力标量值变化 cb(value, oldValue, physicalId)
dev.onProperty(property, cb);                  // 低层：底层属性变化（兼容/调试用）
dev.onMessage(cb);                             // 低层：原始消息

// —— 读取（异步，返回数组，顺序同 deviceMap 物理 ID）——
const vals = await dev.readValue(capability);  // 解析后的能力值，如 [72]
const raw  = await dev.read(property);         // 属性缓存原始值

dev.isMapped();                                // 可选设备先判断
DeviceAPI.params;                              // 启动参数
DeviceAPI.log('info', 'msg', { meta });        // 回传日志到宿主聚合
DeviceAPI.onSystemLog(entry => {});            // 设备离线等系统日志
⚠️

连续数值（压力/重量/距离）优先用 readValue/onValue（能力语义值），不要依赖 read/onProperty 的裸属性名——后者仅作兼容调试。设备离线时下行调用不抛错，只推 warn 系统日志。

提交前检查清单

  • ☐ manifest 内联、id 唯一且等于目录名、version 合法 semver、显示名用 title。
  • ☐ 页面已引入 <script src="/bridge-api/device-api-bridge.js"></script>，所有设备交互走 DeviceAPI，操作前 await DeviceAPI.ready。
  • ☐ 可选设备（required:false）都 isMapped() 判断后再用。
  • ☐ 资源引用仅相对路径或 /bridge-api/；外部 origin 已在 manifest allowedOrigins 声明。
  • ☐ devices[].capabilities 与 backend/devices/registry.js 对得上。
  • ☐ 改动已有游戏时已 bump version（CI 漂移检查：内容变、版本不变会构建失败）。
  • ☐ 在 play-registry/ 下 npm run build && npm test 通过。
  • ☐ 用 npm run electron:debug 起客户端，在「在线游戏」里实际启动一局（可用虚拟设备）。
  • ☐ 含电击/锁定等敏感能力已在 PR 描述中说明。

获取并运行客户端

控制面板客户端就是本仓库本身——clone 后用 npm 直接跑起来，无需单独下载安装包。客户端会自带内置后端（监听 127.0.0.1:5278，提供 /bridge WebSocket 与 /bridge-api/device-api-bridge.js），你调试游戏时连的就是它。

git clone git@github.com:jiandanzhineng/control-panel.git
cd control-panel
npm install            # 首次，安装依赖
npm run electron:debug # 启动客户端并开启调试端口(推荐调试时用)
  • npm run electron:debug：调试推荐。= electron:dev + 开启 CDP 端口 9224，可直接调 Electron 里的游戏页面（见下方「调试游戏」）。
  • npm run electron:dev：普通开发模式，自动复用/启动 vite（5173）并拉起 Electron，但不开调试端口。

两个 dev 脚本都内置 --local-registry：启动时自动构建 play-registry/.site、在本机 4178 端口起本地游戏站，并把客户端「在线游戏」源指向它——你在 play-registry/games/ 新写的游戏会直接出现在客户端里，可以完整走「映射设备 → 启动」流程试玩，无需先上架。要改回线上远程源：直接 node tools/electron-dev.js（不带 --local-registry），或设环境变量 GAME_REGISTRY_URL 指定任意 registry。

⚠️

若启动时 5173 已被你先前开的 vite 占用，脚本会复用它，此时「在线游戏」webview 首页可能仍指向远程站（registry 数据仍是本地 4178）——先关掉已有 vite，让脚本自己拉起前端。

开启开发者模式（外部本地游戏放行）

默认情况下，只有客户端内置浏览器加载的游戏能连后台控制设备。要用外部浏览器/任意本地端口调试自研游戏，需先在客户端里打开开发者放行：

  1. 客户端左侧进入 网络配置 / 服务 页。
  2. 找到 「开发者：外部本地游戏放行」，勾选 「允许外部本地游戏连接」。
  3. 开启后，本机 localhost / 127.0.0.1 任意端口的页面即可连后台；非回环地址（如手机同局域网访问 http://192.168.x.x:8080）需在下方 「添加来源」 显式加入。
⚠️

安全提示：开启后你浏览器访问过的本地页面就具备控制真实设备的能力，仅在本机开发调试时开启，用完请关闭。

调试游戏

方式 A · 在客户端内调试（Electron 页面，CDP 9224）：游戏最终跑在 Electron 里，要调它加载的真实页面就得连 Electron 的调试端口。用 npm run electron:debug 启动客户端（自动开 CDP 端口 9224），在客户端「在线游戏」启动你的游戏后，用任一 Chrome 打开 chrome://inspect → Configure 加入 127.0.0.1:9224 → 在 Remote Target 里对你的游戏页面点 inspect，即可得到完整 DevTools（控制台/网络/DOM/断点），与本机调网页一致。

npm run electron:debug   # 启动客户端并开启 CDP 端口 9224
# 浏览器打开 http://127.0.0.1:9224/json 能看到页面列表即成功
# 再用 chrome://inspect 连 127.0.0.1:9224 调试对应页面
# 打包后的 exe 调试改用 npm run electron:debug:prod（端口 9222）

方式 B · 外部浏览器（独立端口，改 bridge 引用）：先在客户端开启「外部本地游戏放行」(见上一节)，游戏页面改用 bridge 的绝对地址，再用任意本地端口打开页面 F12 调试——脚本会自动连回后台，不受页面端口影响。上架前记得把引用改回相对的 /bridge-api/...。

<!-- 外部调试时改用绝对地址引用 bridge（上架时改回 /bridge-api/...）-->
<script src="http://127.0.0.1:5278/bridge-api/device-api-bridge.js"></script>
⚠️

bridge 的 WebSocket 目标跟随脚本的加载来源：从 127.0.0.1:5278 加载就连本地后端，从别处加载就连别处。所以不要把脚本下载镜像到自己服务器、CDN 或本地静态目录用——那样 DeviceAPI.ready 永远不会 resolve。游戏网站上也不会放这个脚本，唯一的合法来源就是面板后端（/bridge-api/ 相对路径或 127.0.0.1:5278 绝对地址）。

外部调试时没有面板替你传参，可用 URL query 直接注入设备映射与启动参数（bridge 脚本会自动解析，注意 URL-encode）：

# deviceMap={"sensor":["vdev01"],"motor":["vdev02"]}  params={"durationSec":60}
http://localhost:8080/index.html?deviceMap=%7B%22sensor%22%3A%5B%22vdev01%22%5D%2C%22motor%22%3A%5B%22vdev02%22%5D%7D&params=%7B%22durationSec%22%3A60%7D

无实机时：用 tools/vdev-cli 起虚拟设备，注入输入并检查设备命令记录，不用真实硬件也能测；创建后在客户端启动游戏的设备映射里就能选到它。注意它默认连 127.0.0.1:3000，Electron 内置后端在 5278，要用 -b 指定：

cd tools/vdev-cli
node cli.js create --id=vdev01 --type=QIYA -b http://127.0.0.1:5278  # 建虚拟气压传感器
node cli.js set --id=vdev01 --pressure=25 -b http://127.0.0.1:5278   # 注入压力值
node cli.js list -b http://127.0.0.1:5278                            # 查看全部虚拟设备

Electron 调试的更多细节（主进程 Node inspector、打包后 exe 调试等）见仓库 docs/guides/ELECTRON_DEBUG.md。

站点构建与自测

这一步针对网站游戏（放在 play-registry/games/、走在线游戏中心发布）：

cd play-registry
npm install          # 首次
npm run build        # 校验并生成 registry.json + packages/*.zip 离线包
npm test             # 运行测试
npm run serve        # 构建整站到 .site/ 并本地预览

构建会校验：内联 manifest 存在且 id == 目录名、semver 合法、id 全局唯一、资源引用仅相对路径 / /bridge-api/ / 已声明 allowedOrigins；同时产出逐文件 sha256 清单（registry schema v2）。CI 上还会做版本漂移检查（见「manifest 规范」）。
