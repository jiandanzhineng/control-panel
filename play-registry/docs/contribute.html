投稿与奖励

把你的玩法上架到玩法库 · 投稿送硬件 + Token 套餐

玩法 = 自包含网页。完成后无需 GitHub 账号：将游戏根目录打成 ZIP，或准备公开 GitHub/GitLab 仓库地址，在投稿工作台提交。人工审核通过后，平台会生成正式游戏包和 registry.json；玩家随即能在控制面板的「玩法库」里直接看到、直接玩。

投稿奖励

投稿通过审核并上架后，可获得硬件 + Token 套餐。具体套餐内容、发放方式和适用设备请咨询客服。

投稿流程

1

完成自包含游戏

阅读 快速开始 和开发规范。游戏根目录须包含 index.html、内联 game-manifest 及所需资源。

2

检查 manifest 与设备安全

id 用英文 kebab-case，version 使用合法 semver；资源只用相对路径或 /bridge-api/。请在游戏结束和异常路径主动停止设备。

3

本地自测并准备投稿

用浏览器或控制面板客户端测试玩法。ZIP 投稿时，将游戏根目录内容打包，不能额外嵌套一层目录；也可准备公开 GitHub/GitLab 仓库地址。

4

在投稿工作台提交

打开投稿工作台注册账号，填写玩法说明后上传 ZIP，或提交公开 Git 地址。ZIP 由浏览器鉴权直传至隔离区。

5

人工审核 + 上线

审核员查看源包或 Git 地址，并在隔离环境测试安全性与设备兼容性。批准后平台同步发布；通常 1–3 个工作日内反馈。

6

联系领取奖励

上架后扫码加客服微信报你的玩法 id，硬件 + Token 套餐细节由客服确认。

审核标准

  • 自包含：游戏只依赖相对路径资源 + /bridge-api/ 桥接脚本，不引外部 CDN；HTML/CSS/JS 中的根绝对路径会被构建拦截。
  • 外部请求显式声明：确需访问外部服务时，在 manifest 增加 allowedOrigins，例如 ["https://api.example.com"]；未声明的 https://、// 和非 /bridge-api/ 根路径会构建失败。
  • 元数据合规：id 唯一、version 合法 semver、devices/params 声明完整；内容变更必须同步 bump version。
  • 安全停机：游戏结束/异常退出时不能让设备停留在危险状态（电击不停、电机满功率）。宿主有 close 兜底，但游戏内也应主动 stop()。
  • 敏感内容标注：含电击、长时间锁定等强刺激玩法的，必须在描述里标注，参数给合理上限与默认值。
  • 不碰文件系统：游戏跑在沙箱 iframe 里，不能尝试访问本机文件、发起除本机 bridge 外的网络请求。

FAQ

玩法更新怎么发版？

更新内容后，把 manifest 的 version bump 一档（按 semver：修复 1.0.1、新增能力 1.1.0、破坏性改动 2.0.0），重新上传 ZIP 或更新公开 Git 地址后新建投稿。平台会校验版本和内容指纹；批准后面板按版本号判定「线上较新」。

能引用第三方库吗？

可以，但必须把库文件放进玩法目录里用相对路径引用（自包含）。不引外部 CDN——玩法要在离线/纯内网环境也能跑。

我的玩法需要新设备/新能力怎么办？

新设备能力是后端能力层的事，不在玩法投稿范围内。先加客服沟通设备接入，能力上线后玩法就能声明使用。

Token 怎么用？

Token 套餐和硬件权益以客服说明为准，具体内容、发放方式和使用规则请向客服查询。
