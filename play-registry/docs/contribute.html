投稿与奖励

把你的玩法上架到玩法库 · 投稿送硬件 + Token 套餐

玩法 = 自包含网页。建议先 clone 本仓库，在 games/ 目录参考现有游戏，用 Claude Code 或 Codex 辅助写一个新游戏。提交 PR 后，CI 自动构建 registry.json 并发布到玩法网站。玩家在控制面板的「玩法库」里直接看到、直接玩。

投稿奖励

投稿通过审核并上架后，可获得硬件 + Token 套餐。具体套餐内容、发放方式和适用设备请咨询客服。

投稿流程

1

clone 仓库

先 clone 本仓库，进入 play-registry/，阅读 快速开始 和现有 games/ 目录。

2

参考现有游戏写新玩法

新建 games/<your-id>/，用 Claude Code 或 Codex 参考现有游戏实现 index.html / game.js。id 用英文 kebab-case，全局唯一。

3

本地构建 + 自测

在 play-registry/ 下跑 npm run build && npm test。构建会校验 semver 版本、id 唯一、资源引用路径、外部 origin 声明，并生成离线包与逐文件 sha256 清单。

4

提交 PR

Fork 仓库 → 新分支提交 games/<your-id>/ → 发 PR 到 main。PR 描述里写清玩法意图、所需设备、是否含惩罚/电击等敏感内容。

5

审核 + 上线

维护者审核安全性与设备兼容性，合并后 CI 自动发布。通常 1–3 个工作日内反馈。

6

联系领取奖励

上架后扫码加客服微信报你的玩法 id，硬件 + Token 套餐细节由客服确认。

审核标准

  • 自包含：游戏只依赖相对路径资源 + /bridge-api/ 桥接脚本，不引外部 CDN；HTML/CSS/JS 中的根绝对路径会被构建拦截。
  • 外部请求显式声明：确需访问外部服务时，在 manifest 增加 allowedOrigins，例如 ["https://api.example.com"]；未声明的 https://、// 和非 /bridge-api/ 根路径会构建失败。
  • 元数据合规：id 唯一、version 合法 semver、devices/params 声明完整；内容变更必须同步 bump version。
  • 安全停机：游戏结束/异常退出时不能让设备停留在危险状态（电击不停、电机满功率）。宿主有 close 兜底，但游戏内也应主动 stop()。
  • 敏感内容标注：含电击、长时间锁定等强刺激玩法的，必须在描述里标注，参数给合理上限与默认值。
  • 不碰文件系统：游戏跑在沙箱 iframe 里，不能尝试访问本机文件、发起除本机 bridge 外的网络请求。

FAQ

玩法更新怎么发版？

改 games/<id>/ 里的内容，把 manifest 的 version bump 一档（按 semver：修复 1.0.1、新增能力 1.1.0、破坏性改动 2.0.0），重新跑 build + test，提 PR。CI 会对比线上 registry 的内容指纹；内容变了但 version 没变会拒绝发布。合并后面板侧会按版本号判定「线上较新」，玩家刷新玩法库即看到新版本。

能引用第三方库吗？

可以，但必须把库文件放进玩法目录里用相对路径引用（自包含）。不引外部 CDN——玩法要在离线/纯内网环境也能跑。

我的玩法需要新设备/新能力怎么办？

新设备能力是后端能力层的事，不在玩法投稿范围内。先加客服沟通设备接入，能力上线后玩法就能声明使用。

Token 怎么用？

Token 套餐和硬件权益以客服说明为准，具体内容、发放方式和使用规则请向客服查询。
