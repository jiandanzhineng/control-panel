快速开始

推荐流程：clone 本仓库 · 用 Claude Code / Codex 参考现有游戏改出新玩法

UnderSilicon 玩法 = 一个自包含网页。最快的开发方式不是从零写空白项目，而是 clone 本仓库，让 Claude Code 或 Codex 读取现有游戏，按你的玩法想法改出一个新游戏目录。

💡

推荐给 AI 的上下文：先让它阅读 backend/games/ 和 play-registry/games/ 里最接近的现有游戏，再要求它复制结构、改玩法逻辑、更新 manifest，并保持 DeviceAPI 调用方式一致。

推荐开发流程

1

clone 本仓库

把控制面板仓库 clone 到本地，进入仓库根目录后重点关注 backend/games/ 和 play-registry/games/。

2

选一个参考游戏

找一个设备类型、交互节奏或惩罚逻辑最接近的现有游戏。优先参考已经能构建通过的目录，而不是从空文件开始。

3

让 Claude Code / Codex 改出新玩法

让 AI 先阅读参考游戏，再复制到新的 games/<your-id>/ 目录，按你的玩法规则修改 UI、参数、设备映射和 DeviceAPI 调用。

4

检查 manifest 和资源路径

确认新游戏的 id 全局唯一、version 是合法 semver、devices/params 声明完整，资源只使用相对路径或 /bridge-api/。

5

构建 + 自测

在 play-registry/ 下运行 npm run build && npm test。再用浏览器或控制面板客户端打开本地游戏网站，确认游戏能启动。

6

打包并投稿

将游戏根目录内容打成 ZIP（不要嵌套外层目录），或准备公开 GitHub/GitLab 地址。在投稿工作台填写玩法意图、所需设备，以及是否包含电击/锁定等敏感内容。

给 AI 的提示词

请先阅读 backend/games/ 和 play-registry/games/ 里最接近的现有游戏。
我要做一个新的玩法：<描述玩法规则>。
请复制参考游戏结构到 play-registry/games/<your-id>/，
更新 game-manifest、UI、参数、设备声明和 DeviceAPI 调用。
保持资源自包含，跑 npm run build && npm test，最后说明改了哪些文件。

目录结构

每个玩法一个目录，至少包含 index.html。可以再拆出 game.js、style.css，但更重要的是沿用参考游戏已经验证过的结构。

play-registry/games/
└── your-id/
    ├── index.html        # 主页面和内联 manifest
    ├── style.css         # 可选
    └── game.js           # 可选

关键规则（必须遵守）

  • 元数据必须内联在 index.html 的 <script id="game-manifest"> 中，type 用 application/json。不用单独的 manifest.json。显示名字段是 title。
  • id 必须等于目录名，kebab-case、全局唯一；版本号必须是合法 semver（如 1.0.0、2.1.3）。构建脚本都会校验。
  • 必须引入桥接脚本：<script src="/bridge-api/device-api-bridge.js"></script>——它创建 window.DeviceAPI。设备交互一律走 DeviceAPI，不要自己开 WebSocket 连 /bridge，桥接脚本已经处理好了连接、重连、属性缓存。
  • 资源引用只能用相对路径或 /bridge-api/ 开头的绝对路径。禁止根绝对路径（如 /games/foo/x.js）——会被面板 gameProxy 误判为本地资源，构建 lint 会拦截；确需外部请求时在 manifest 加 allowedOrigins。
  • 可选设备先 isMapped() 再用。必填设备由宿主保证已映射，可选设备可能为空数组。
  • 改动已有游戏必须 bump version。CI 会对比线上 registry 内容指纹，内容变了版本没变会拒绝发布。

本地调试

最顺的试玩路径是直接用开发脚本启动客户端：npm run electron:dev / npm run electron:debug 都内置本地游戏源——启动时自动构建 play-registry/.site 并在本机 4178 端口起本地游戏站，客户端「在线游戏」里直接就能看到、启动你新写的游戏。electron:debug 额外开启 CDP 端口 9224，可以用 Chrome DevTools 调 Electron 里的游戏页面。

外部浏览器调试、URL 注入参数、虚拟设备（无实机测试）等更多姿势，见 Agent 开发指南 · 调试游戏。
