快速开始

面向第一次写玩法的开发者 · 5 分钟跑通

UnderSilicon 玩法 = 一个自包含的网页。逻辑和 UI 都在一个 HTML/JS 里，通过注入的 DeviceAPI 桥接控制真实设备。你不需要独立 JS 引擎，也不需要逻辑/UI 分离——写游戏就是写网页。

💡

核心承诺：游戏页面代码不区分自己跑在宿主里还是直接浏览器打开。两种入口下读同样的 DeviceAPI.params / DeviceAPI.deviceMap，降级逻辑由桥接统一兜底。

目录结构

每个玩法一个目录，至少包含 index.html。可以再拆出 game.js、style.css。

games/
└── my-game/
    ├── index.html        # 主页面（逻辑+UI+内联元数据，单文件即可运行）
    ├── style.css         # 可选
    └── game.js           # 可选（也可内联进 html）

三步写一个玩法

1

建目录 + 内联元数据

在 games/my-game/index.html 的 <head> 内联一段 <script id="game-manifest">，声明 id / title / version / devices / params。

2

引入桥接 + 写逻辑

页面里 <script src="/bridge-api/device-api-bridge.js"></script>，然后 await DeviceAPI.ready 之后再操作设备。

3

构建 registry + 提交

跑 npm run build && npm test，提交到 main 分支，CI 自动发布到玩法网站。

最小完整示例

下面是一个能跑的最小玩法：监听压力传感器，超阈值就电击。

<!DOCTYPE html>
<html lang="zh-CN">
<head>
<meta charset="utf-8" />
<title>压力寸止 demo</title>
<script type="application/json" id="game-manifest">
{
  "id": "my-game",
  "title": "我的玩法",
  "description": "压力超阈值就电击",
  "version": "1.0.0",
  "devices": [
    { "id": "sensor", "capabilities": ["sphincterPressure"], "required": true },
    { "id": "punish", "capabilities": ["shock"], "required": false }
  ],
  "params": [
    { "key": "threshold", "type": "number", "default": 80, "label": "压力阈值" }
  ]
}
</script>
<script src="/bridge-api/device-api-bridge.js"></script>
</head>
<body>
<h2>压力: <span id="gauge">-</span></h2>
<script>
(async function () {
  await DeviceAPI.ready;
  const threshold = DeviceAPI.params.threshold;

  DeviceAPI.device('sensor').on('sphincterPressure', 'pressureChange', (data) => {
    const val = data.props.pressure;
    document.getElementById('gauge').textContent = val;
    if (val > threshold && DeviceAPI.device('punish').isMapped()) {
      DeviceAPI.device('punish').invoke('shock', 'start', { voltage: 30 });
    }
  });

  DeviceAPI.log('info', '玩法已启动', { threshold });
})();
</script>
</body>
</html>

关键规则（必须遵守）

  • 元数据必须内联在 index.html 的 <script id="game-manifest"> 中，type 用 application/json。不用单独的 manifest.json。
  • 版本号必须是合法 semver（如 1.0.0、2.1.3）。构建脚本会校验。
  • 资源引用只能用相对路径或 /bridge-api/ 开头的绝对路径。禁止根绝对路径（如 /games/foo/x.js）——会被面板 gameProxy 误判为本地资源，构建 lint 会拦截。
  • 设备交互一律走 DeviceAPI，不要自己开 WebSocket 连 /bridge。桥接脚本已经处理好了连接、重连、属性缓存。
  • 可选设备先 isMapped() 再用。必填设备由宿主保证已映射，可选设备可能为空数组。

本地调试

玩法页面可以直接浏览器打开调试——它会连到本机后端的 WebSocket Bridge。流程：

  1. 启动控制面板后端（它会监听 /bridge WebSocket 和 /bridge-api/device-api-bridge.js 静态资源）。
  2. 把你的玩法目录挂到能被面板扫描的位置，或在面板「玩法库」里用外部 URL 加载。
  3. 浏览器开发者工具直接断点调试页面 JS，和调试普通网页完全一样。
